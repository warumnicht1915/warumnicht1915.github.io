마크다운 파서는 "정규식 몇 개면 되겠지" 하고 시작했다가 반드시 한 번 막히는 주제입니다.
이 블로그가 쓰는 파서를 어떤 구조로 만들었는지 정리해 둡니다.

<!--more-->

## 첫 번째 시도: 정규식 나열

처음엔 이렇게 시작했습니다.

```js
html = md
  .replace(/^# (.*)$/gm, '<h1>$1</h1>')
  .replace(/\*\*(.+?)\*\*/g, '<strong>$1</strong>')
  .replace(/`(.+?)`/g, '<code>$1</code>');
```

10분 만에 동작하는 것처럼 보입니다. 그리고 다음 입력에서 바로 무너집니다.

```text
`이 안의 **별표** 는 강조되면 안 된다`
```

코드 스팬 안의 별표가 그대로 `<strong>` 으로 바뀝니다.
치환 순서를 바꿔도, 이번엔 코드 블록 안의 `# 주석` 이 제목이 되는 식으로
문제가 자리만 옮겨 다닐 뿐입니다.

> [!WARNING]
> 마크다운은 문맥에 따라 같은 문자의 의미가 달라집니다.
> 순수한 문자열 치환만으로는 원리적으로 정확해질 수 없습니다.

## 두 번째 시도: 블록에서 인라인으로

지금 쓰는 구조는 이렇습니다.

1. **블록 파서** — 입력을 줄 단위로 훑으면서 제목·문단·리스트·코드펜스·표·인용을 나눈다.
2. **인라인 파서** — 각 블록의 내용에만 강조·링크·코드 스팬을 적용한다.

핵심은 블록 파서가 코드펜스를 만나면 **인라인 파서를 아예 호출하지 않는다**는 점입니다.
문맥 문제가 구조적으로 사라집니다.

```js
// 코드 펜스를 만나면 닫는 줄까지 통째로 소비한다
const fence = line.match(/^(\s*)(`{3,}|~{3,})\s*([^\s`]*)\s*(.*)$/);
if (fence) {
  const closer = new RegExp('^\\s*' + fence[2][0] + '{' + fence[2].length + ',}\\s*$');
  const buf = [];
  i++;
  while (i < lines.length && !closer.test(lines[i])) { buf.push(lines[i]); i++; }
  i++;
  out += codeBlock(buf.join('\n'), fence[3]);
  continue;   // 인라인 파서를 거치지 않는다
}
```

## 인라인 안에서도 순서가 있다

블록 안으로 들어와도 문제가 하나 더 남습니다.
인라인 코드 스팬 안에서는 여전히 어떤 변환도 일어나면 안 됩니다.

그래서 인라인 파서는 **자리표시자(placeholder)** 를 씁니다.

1. 코드 스팬과 원시 HTML을 먼저 떼어내 배열에 저장하고, 그 자리에 표시만 남긴다
2. 남은 텍스트에만 강조·링크 변환을 적용한다
3. 마지막에 표시를 원래 조각으로 되돌린다

```js
const slots = [];
const hold = (html) => { slots.push(html); return MARK + (slots.length - 1) + MARK; };

s = s.replace(/`([^`\n]+)`/g, (_, code) =>
  hold('<code class="inline-code">' + esc(code) + '</code>'));
```

자리표시자에 쓸 문자는 **본문에 절대 나올 수 없는 것**이어야 합니다.
`@@1@@` 같은 문자열은 본문에 그대로 등장할 수 있어서 안전하지 않습니다.
그래서 널 문자(U+0000)를 씁니다.

```js
const MARK = String.fromCharCode(0);
```
